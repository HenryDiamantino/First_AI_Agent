# RF01 — Chat Interativo via Terminal com Agente de IA

| Campo | Valor |
|---|---|
| ID | RF01 |
| Nome | Chat interativo via CMD com OpenAI e Strands Agents |
| Tipo | Requisito Funcional |
| Prioridade | Alta |

## 1. Descrição

O sistema deve implementar um agente de IA "super simples" que roda localmente na máquina do usuário, em Python, acessível via terminal (CMD/PowerShell). O agente utiliza o **AWS Strands Agents SDK** como framework de orquestração e a **API da OpenAI** como provedor do modelo de linguagem (LLM).

O usuário digita mensagens no terminal e recebe respostas do modelo, em um loop contínuo de pergunta/resposta, até solicitar o encerramento.

## 2. Atores

- **Usuário**: pessoa que interage com o agente pelo terminal.

## 3. Entradas

- Mensagens de texto digitadas pelo usuário no terminal.
- Chave da API OpenAI, lida do arquivo `.env` na raiz do projeto (variável `OPENAI_API_KEY`).

## 4. Saídas

- Respostas de texto geradas pelo modelo, exibidas no terminal.

## 5. Regras de Negócio

- **RN01 — Memória de sessão persistida em arquivo**: o agente deve manter o histórico da conversa com contexto multi-turno e persisti-lo em arquivos locais (via `FileSessionManager` do Strands). Ao reabrir o programa com a mesma sessão, o contexto anterior é restaurado.
- **RN02 — Loop de interação**: o programa deve executar em loop: ler entrada do usuário → enviar ao agente → exibir resposta → aguardar nova entrada.
- **RN03 — Comando de saída**: o usuário encerra a sessão digitando um comando de saída (ex.: `sair`, `exit` ou `Ctrl+C`).
- **RN04 — Configuração via .env**: a chave `OPENAI_API_KEY` deve ser carregada de um arquivo `.env` (via `python-dotenv`). Se a chave não estiver configurada, o programa deve exibir mensagem clara de erro e encerrar.
- **RN05 — Entrada vazia**: entradas vazias ou contendo apenas espaços devem ser ignoradas (não enviadas ao modelo).
- **RN06 — Falha de comunicação**: erros de rede ou da API (ex.: chave inválida, quota excedida) devem exibir mensagem amigável no terminal sem travar o programa; o loop deve continuar após o erro.
- **RN07 — Tool de data/hora**: o agente deve dispor de uma tool que retorne a data e hora atuais, usada automaticamente quando a pergunta depender dessa informação (ex.: "que dia é hoje?", "que horas são?").

## 6. Fluxo Principal

1. Usuário executa o script Python no terminal (ex.: `python main.py`).
2. O sistema carrega `OPENAI_API_KEY` do arquivo `.env`.
3. O sistema inicializa o agente Strands com o modelo OpenAI.
4. O sistema exibe prompt de boas-vindas/instruções.
5. Usuário digita uma mensagem.
6. O sistema envia a mensagem ao agente e exibe a resposta.
7. Retorna ao passo 5 até o usuário digitar o comando de saída.
8. O sistema exibe mensagem de encerramento e finaliza.

## 7. Critérios de Aceite

- [ ] O programa inicia via `python <script>.py` sem erros, com `.env` válido.
- [ ] Mensagens enviadas recebem respostas coerentes do modelo OpenAI.
- [ ] O agente responde corretamente a perguntas que dependem de contexto anterior da sessão (memória funciona).
- [ ] Ao fechar e reabrir o programa, o histórico da conversa anterior é restaurado (persistência em arquivo).
- [ ] Perguntas como "que horas são?" retornam a data/hora real atual (tool funciona).
- [ ] Digitar `sair`/`exit` (ou `Ctrl+C`) encerra o programa graciosamente.
- [ ] Sem `OPENAI_API_KEY` configurada, o programa informa o problema e não quebra com stack trace crú.
- [ ] Erros de API exibem mensagem amigável e o chat continua funcionando.

## 8. Dependências e Restrições Técnicas

- **Linguagem**: Python (execução local, sem servidor/container).
- **Framework**: `strands-agents` com suporte a OpenAI (`strands-agents[openai]`).
- **Modelo**: modelo OpenAI (ex.: `gpt-4o-mini`); o modelo deve ser facilmente configurável no código.
- **Configuração**: `python-dotenv` para leitura do `.env`.
- **Requisito de ambiente**: conexão com internet e chave de API OpenAI válida.

## 9. Fora de Escopo

- Interface gráfica (GUI) ou interface web.
- Streaming de resposta token a token.
- Tools adicionais além da de data/hora (busca web, calculadora, etc.).
- Comandos auxiliares além do encerramento (`/limpar`, `/ajuda`, etc.).
- Autenticação de usuários, logging estruturado, deploy.
